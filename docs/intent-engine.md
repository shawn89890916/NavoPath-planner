# Intent Engine pilot

Scope: a bounded Tree view loader experiment; real navigation, drop geometry, task styling and plugin lifecycles stay unchanged. Existing pointer-enter/focus warming remains the fallback. Only the already existing idempotent PlanningView module loader is eligible. No new dependencies, network APIs, settings, telemetry, global pointer listeners or timers.

The menu samples mouse motion only while open, not during dragging. Three time-ordered points estimate direction and velocity; reversals, braking, jitter, pauses and degenerate targets are rejected. The existing target rectangle is read only after a valid prediction, at most once per 16ms. The projected segment is limited to 100ms/120px. One predictive loader attempt per menu opening. Opening/canceling/leaving or repositioning resets the pointer history. The existing loader deduplicates imports; loaded JS modules cannot be unloaded independently. No speculative plugin activation or data mutation.

## Validation and further integration

Compare existing click-only (A), hover/focus preload (B), and predictive preload plus fallback (C) in a fresh renderer per trial, with cold and warm module caches. Replay deliberate, diagonal, overshoot, reversal, click-away and keyboard routes; record hover and click timestamps, import start/end and next usable render locally. Report p50/p95 click-to-usable, prediction precision, wasted preloads, additional main-thread work and renderer memory. Unit tests cover only geometric and lifecycle primitives, not actual latency. Do not keep a predictor in any hot path without measurable benefit over B. Keep existing bundle budgets, no relaxing limits.

Drag projection: current logical hit-test and projection already use actual coordinates. Speculative geometry would require extra layout reads or validated snapshots; defer until profiling shows a bottleneck. Do not change actual hit/drop or task styles. Likewise defer task details, plugins, month, Dock and submenu prediction until actual cold-path costs or unintended menu exits are measured. Use existing module loaders and motion infrastructure; never mount third-party code before explicit activation. This pilot does not complete the broader Intent Engine roadmap.

## Second slice: shared native planning targets and controlled Chromium validation

All native planning views in the Tasks menu (Tree and installed native board/matrix views) use the same idempotent loader; extension-owned custom mounts are not warmed. Skip disabled, selected and geometrically clipped targets. Reset on window blur, retain pointer-enter/focus fallback. Reuse existing Chromium fixture runner; separate PR job runs the intent fixture only, full preflight and Desktop Release exercise it in a separate isolated process, preserving the original fixture timeout. The fixture uses the actual menu, DOM geometry, React events and a controlled 110ms asynchronous loader, comparing click-only, hover/focus and intent with five trials at each width. This isolates lead-time mechanics; synthetic trajectories, offscreen focus emulation and controlled loading are not evidence of actual production import latency or real human precision. Production memory and drag hot-path performance remain unmeasured. Do not claim a real-world speedup or enable speculative drag/third-party activation from this fixture alone.

Prior controlled Windows run 46005953318 (before integration with Beta 136): 1280px A/B/C p50 110.4/90.8/28.1ms; 420px 110.9/90.5/27.1ms; median lead 61.7/62.1ms. Guard assertions passed. Revalidate after merging parallel changes. Production import cost and real user precision remain unmeasured.

## Beta 138 — recurring interaction cost

Prioritize confirmed-state computation reuse over speculative DOM geometry. Drag projection visits only the affected interval and rejects over-budget ranges before allocation; unchanged destination animations survive adjacent target changes and all current translation reads precede animation writes. Existing logical hit testing, actual drop/undo, source/target styling, reduced motion and cleanup remain authoritative. The browser fixture exercises real WAAPI animations and records creation counts; this is not an end-to-end drag FPS benchmark. Timeline multi-day rendering reuses the already memoized scheduled list, daily width uses the ResizeObserver result (one fallback read at most), and conflict layout invalidates only when committed draft time changes. Month scroll lookup uses binary search on existing sorted week geometry. Tests cover exhaustive offset parity, budget limits, week boundaries and browser animation identity. No prediction of mutations, no new runtime dependency or persistent cache. Speculative cross-container layout, multi-signal hierarchy changes, adjacent date warming and adaptive scheduling remain deferred until profiling shows a net benefit; no extra DOM measurement on pointer movement to implement them.
