# Reading extension (MVP)

Reading is an opt-in community plugin, packaged for offline installation in desktop-beta. Install and enable it from Settings → Plugins. It contributes a dedicated Tasks group and a reading shelf; it does not replace core task blocks. Reading tasks are ordinary tasks, linked to an immutable book ID. The existing task timeline, timer and activity history operate normally. Completing one reading task does not finish its book. Books have independent state and percentage/page/chapter progress; actual, planned and engagement-weighted recorded time are kept distinct. Metrics Overview uses its existing range-clipped scheduled entries and recorded time entries, grouped by book.

The library uses the account-scoped extension value store and offline cache. A read before mutation and an edit guard protect against already-observed changes. On an uninitialized cloud device, a failed first read does not become an editable empty library; a previously confirmed empty library or cached data remains editable offline. The existing extension value transport is last-write-wins across concurrent devices, not an atomic per-book merge; simultaneous offline editing is not yet guaranteed conflict-free. Disable/uninstall hides the contribution without deleting the core tasks or the library; retained task links allow retained time entries to remain attributable. Task creation persists the book link first, then the core task; an interruption can leave an inert link, which contributes no duration. Core activity-history undo handles the task; book edits have a guarded immediate undo. No new timer or capture system.

## Follow-up: WeRead connector

Tencent's official [WeChatReading repository](https://github.com/Tencent/WeChatReading) documents an API-key based agent gateway with shelf, progress and reading statistics. Its profile documentation identifies book.recordReadingTime as cumulative seconds, and /book/getprogress returns progress and cumulative duration. Before live integration, verify current endpoints, key authorization, CORS/network path, secure desktop credentials, rate limits, and reading interval granularity against a real explicitly authorized account. Do not store API keys in synced library data or generate scheduled blocks from cumulative seconds. Add source IDs and idempotent import preview, keep source totals separate from overlapping local tracked time, and record exact intervals only when provided. Direct integration, per-book merge and richer trend/heatmap views are not included in this MVP.

## Verification
- Model tests: independent state/progress, stable identity, valid storage, guarded book undo, multiple tasks and schedule/entry deduplication, invalid and cross-midnight intervals.
- Manual regression: install/enable/disable/reinstall, book creation/edit/undo, task creation/drag/complete/undo, progress independently of completion, restart and account switch; check desktop/compact/mobile, light/dark, and workspace radius extremes.
- Metrics: filters and range should apply through existing facts; no separate time collector or third-party dependencies.

## WeRead shelf integration

Desktop Reading now uses the existing encrypted connection, explicitly previews book selection, imports public or user-selected private titles and optionally links a book to an existing local ID. Imported books follow provider progress; editing their local status/progress switches to independent manual progress. Existing books retain their IDs and task associations. Auto-import is opt-in and uses a baseline of already observed shelf IDs, excluding private and matching existing books. A replacement key creates a distinct device connection ID; after reconnect, explicitly relink books (the API does not expose a verified account identifier). Never delete local history on remote shelf removal. Refresh on shelf opening/focus or manual action, with at most five recent linked e-books per refresh. No background polling runs while the shelf is closed; this keeps optional Reading sync out of the idle app path. Individual e-books refresh on demand. Weekly provider reading/listening buckets and per-book cumulative seconds are separate from local actual time; no synthetic timeline intervals. Provider progress for audio is not claimed.
